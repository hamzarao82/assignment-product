# Learning log (Advanced Extended edition)

I built a framework-free TypeScript task tracker data layer: strict validation of every external input, retry with timeout and cancellation, an optimistic store with conflict detection, a cache, debounced search, import and export with a dry run, an audit log, an offline queue, redacted diagnostics and an accessible HTML renderer. Before writing new code I audited my first iteration against eight invariants and reproduced twelve real defects with failing tests, so every fix traces to evidence instead of a hunch (the register is in `docs/audit-report.md`). The hardest section was the store (4.7), because rollback, ordering and conflicts had to be one idea; I settled on "visible state is the confirmed list plus pending mutations replayed in order", which turns a rollback into simply removing one mutation and recomputing. The AI mistake I can quote is my own prompt "complete it", which was unbounded and ignored the bounded-prompt rule, and the result let two edits to one task race to the server out of order and let a throwing subscriber strand a mutation, both of which only my reproduction tests exposed. A second mistake was in the tooling: the file-writing step turned my `​`-style escapes into real invisible characters, one of them a line separator that broke a regex literal, so I rewrote the check with explicit code point ranges and no escape sequences. A third was a security test that looked reassuring but was too weak: mutation checking (deleting `escapeHtml` on purpose) showed the property test still passed because random strings almost never contain `<`, so I rebuilt its generator with a hostile alphabet and confirmed it now fails when escaping is removed. The main trade-off is that offline replay is at-least-once, not exactly-once: a request that succeeded but whose acknowledgement was lost is replayed and surfaces as a version conflict, which I chose over risking a silent double-apply. The regression test I am proudest of is "does not apply an earlier accepted edit twice when a later edit conflicts", because without the one-line guard the version silently drifts, and I verified it fails when the guard is deleted. A bug my own test found late was an offline queue that stalled if the connection dropped and returned before the aborted attempt finished unwinding, fixed by restarting replay when work remains. The result is 512 tests, 99.69% line, 96.68% branch and 99.31% function coverage against the 88, 85 and 88 gates, with lint, format check, typecheck and build all passing through `npm run verify`.
