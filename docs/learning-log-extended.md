# Learning log

I built a typed task tracker data layer in TypeScript: a generic `AsyncState<T>`, untrusted-input validation, a retrying and abortable fetcher with a stale-response guard, typed filter/sort/group helpers, a de-duplicating paginated loader, an optimistic store, a TTL cache, debounced search, an escaped HTML renderer and stats. The hardest part was 3.7, the optimistic store, because rolling back one failed mutation must not undo a newer successful one, so I model visible state as the confirmed list plus pending mutations replayed in issue order. After the first review the instructor reproduced three bugs that all came from re-entrancy and ordering my tests had not exercised: `invalidate()` let a pending request re-cache old data, a subscriber calling `loadMore()` from the loading notification started duplicate requests, and a subscriber that updated the store made the next listener receive the same state twice. I fixed each at its root (a per-key generation in the cache, marking the request in flight before notifying, and a notification queue in the store) and added regression tests that I confirmed fail on the old code. The AI mistake I can quote is my prompt "complete it": it was unbounded and ignored the bounded-prompt structure from Section 5, so the AI built sections 3.4 to 3.9 in one pass, and all three bugs sat in the subscriber and invalidation paths that it never stress-tested. A smaller one the compiler caught: `groupTasksByPriority` spread its default buckets and then overwrote them (TS2783), and coverage read 0% until I matched the `vitest` and `@vitest/coverage-v8` versions. If I had more time I would make a throwing listener safe, because today a listener that throws during an optimistic commit leaves that mutation stuck in the pending list. Final result: 147 tests, 98.77% lines and 94.44% branches against the 85% and 80% gates, with lint and typecheck clean.
